# Discovery Graph: DG-0002
**Graph Type:** opportunity

## Core Issue

Participants cannot work on the canvas together yet: a session has no cards, and nothing one participant changes reaches the others.

**Impact/Value:** Enables multi-user collaboration and maintains the <2000ms latency requirement for session updates.

**Discovery Method:** Architectural requirement analysis based on deferred SPEC-0001 risks and project objectives.

## Patterns

### Pattern 1: realtime-sync-implementation

**Applies To:** Quadra Realtime Sync Service  
**Frequency/Recurrence:** Continuous per session.  
**Severity/Urgency:** High  
**Confidence:** High  
**Current State:** Functionality deferred from initial SPEC.  

**Evidence Signals:**

- Supabase Realtime events must be forwarded to every connected NiceGUI client without polling.
- Synchronize multi-user card operations across all active web clients in real time.
- Broadcast database mutations instantly to all listening clients via supabase-py Realtime events.

### Pattern 2: card-operations

**Applies To:** Quadra canvas  
**Frequency/Recurrence:** Every edit in a session.  
**Severity/Urgency:** High  
**Confidence:** High  
**Current State:** A session shows its four quadrants with no cards.  

**Evidence Signals:**

- Participants insert, update, soft-delete, or relocate cards between any of the four quadrants.

### Pattern 3: responsive-card-ui

**Applies To:** Quadra NiceGUI canvas  
**Frequency/Recurrence:** Every edit in a session.  
**Severity/Urgency:** High  
**Confidence:** High  
**Current State:** No card UI exists yet.  

**Evidence Signals:**

- Card creation and movement stay smooth under light network latency, through optimistic UI state or quick confirmation in the Python UI framework.

### Pattern 4: card-metadata

**Applies To:** Quadra card records  
**Frequency/Recurrence:** Every edit in a session.  
**Severity/Urgency:** High  
**Confidence:** High  
**Current State:** No card table exists yet.  

**Evidence Signals:**

- Every card holds its quadrant ID, order index, author identifier and timestamp, which preserve its position and history.

## Pattern Dependency Graph

Realtime sync comes first: card operations reach other clients through it, and the responsive UI confirms against it. Card metadata (quadrant ID and order index) is what card operations change and what every client orders the canvas by.
