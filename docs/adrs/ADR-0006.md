# ADR-0006: Make closure dominate pending operations and overlapping loads

## Context

Earlier collaborative-card landings failed on pending-state races and incomplete loads. A delayed response must not undo closure, restore a rejected overlay or replace a newer complete snapshot with an older partial result.

## Decision

We will make closed canvas state monotonic and invalidate older asynchronous response generations on closure, then replace optimistic overlays with a complete authoritative closed-session snapshot.

## Alternatives Considered

- Disable controls without reconciling pending state: rejected because optimistic cards and movements can remain falsely finalized.
- Roll every pending operation back unconditionally: rejected because some operations committed before closure despite delayed responses.
- Accept responses in arrival order: rejected because older loads and mutation completions can overwrite authoritative newer state.

## Consequences

### Positive

- Closure remains read-only despite delayed successes, failures or loads.
- The displayed finalized snapshot includes pre-closure commits and excludes rejected pending changes.
- One explicit response-generation rule applies to initial loads and later reconciliation.

### Negative

- Canvas state management must track response generations and separate optimistic overlays from authoritative cards.
- Closure may require an additional fully paginated reload.
- A failed reload needs a visible retry state while editing remains disabled.
