# ADR-0004: Persist authoritative session-scoped cards with soft deletion

## Context

Other features consuming cards must agree on ownership and deletion semantics; browser-local authoritative state would diverge across participants.

## Decision

We will make Supabase cards authoritative, enforce session ownership at the card-service boundary, and represent deletion with a retained row carrying deleted_at.

## Alternatives Considered

- Authoritative browser-local card storage: rejected because disconnected or concurrent views could disagree about persisted state.
- Hard deletion: rejected because the strategy explicitly requires deleted cards to be hidden but retained.
- Global card operations without a session parameter: rejected because they cannot enforce the session boundary consistently.

## Consequences

### Positive

- Reloads and connected views share a durable source of truth.
- Deleted card records retain their authorship and temporal data.

### Negative

- Retained deleted rows consume storage and every active-card read must filter them.
- Session validation adds checks to every card mutation.
