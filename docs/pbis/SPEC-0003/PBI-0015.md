# PBI-0015: In src/quadra/canvas.py, make Canvas.start reconcile lifecycle state after Realtime registration. After registering, obtain the authoritative lifecycle status through the existing session-service lifecycle read. If the session is closed, apply closure through the existing monotonic closed latch and generation invalidation, without discarding a closure that arrives through Realtime in the meantime. Also change the load path so that when a closed session's card load fails, the canvas stays closed and read-only, shows the load failure, and offers a retry. A successful retry must render every active card exactly once in the existing deterministic order. Add two integration tests under tests/integration/ for these two behaviours.

## Verification

- [ ] An integration test closes the session between the initial lifecycle read and the Realtime registration, and the canvas ends closed and read-only.
- [ ] A closure that arrives through Realtime while the post-registration lifecycle read is in flight is not lost, and the closed latch is never reverted.
- [ ] An integration test makes a closed session's first card load fail. The canvas stays read-only, shows the load failure (not only the generic load error) and offers a retry.
- [ ] A successful retry renders every active card exactly once in the existing deterministic order, with no soft-deleted cards, and the canvas remains read-only.
- [ ] The existing closure integration tests still pass: test_canvas_closure*.py, test_canvas_closed_load.py, test_canvas_close*.py and test_closure_isolation.py.
- [ ] An open session remains editable, and the card tests for open sessions still pass.
