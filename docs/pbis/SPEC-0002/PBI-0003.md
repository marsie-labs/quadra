## Verification

- [ ] A card inserted by A through card-service appears in B's DOM event log in under 2000ms after commit, with Realtime and NiceGUI WebSocket in the path and no polling
- [ ] Card changes in one session are not dispatched to views of another session
- [ ] Existing session and quadrant events still reach both registered views with original session identity and payload, not filtered as non-card events
- [ ] The last view disconnecting still releases the subscription

## Refinement Protocol

If card notifications cannot share the existing subscription path without breaking session or quadrant delivery, file an architecture-level discovery report rather than adding a second delivery path or polling.
