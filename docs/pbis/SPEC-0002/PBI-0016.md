# PBI-0016: In src/quadra/canvas.py, make every response handler (_submit for inserts, _save_edit for edits, _show_confirmed for moves, and the soft-delete path) and every Realtime fold clear its optimistic entry (_pending, _moving or the edit state) and then rerender from authoritative state in _cards. The rerender must cover the card's current quadrant in _cards and every quadrant the cleared optimistic entry showed it in. A stale response must still be discarded, but it must also trigger that rerender, so _show_confirmed rerenders the current authoritative quadrant as well as the cleared optimistic target. Add integration tests that hold an insert, edit or move response and overlap it with a newer remote edit, move or soft-delete of the same card. They must include the land finding: an older held move to Q2, a newer Realtime move to Q3, and the card ends visible only in Q3 on the initiating canvas.

## Context

Read: `src/quadra/canvas.py`

In canvas.py, read the optimistic overlay state (_pending, _moving, edit state), the _cards store, _submit, _save_edit, _move, _show_confirmed, the soft-delete handler and the Realtime fold. Look for each place a stale response or fold returns early without rerendering, and for places where a render is driven by the overlay instead of _cards. In the Contract, see the Data Models entry that Supabase remains authoritative and pending representations are transient, and the DoD item requiring confirmed relocations to reach another client in less than 2000ms. Existing integration tests in tests/integration/test_canvas_pending_move.py, test_canvas_propagation.py and test_canvas_relocate.py show how a response is held with a controllable barrier. Supabase-backed tests belong in tests/integration/ and use its conftest.py, which loads .env and applies migrations through SUPABASE_DB_URL.

## Verification

- [ ] After an older held move to Q2 is overlapped by a newer Realtime move to Q3, releasing the older response leaves the card visible only in Q3 on the initiating canvas, and Q2 and Q1 show no copy.
- [ ] A stale _show_confirmed response is discarded but rerenders both the current authoritative quadrant and the cleared optimistic target.
- [ ] A held insert response overlapped by a newer remote edit, move or soft-delete of the same card ends with the card shown exactly as _cards states, with no duplicate and no ghost pending entry.
- [ ] A held edit response overlapped by a newer remote edit, move or soft-delete of the same card ends with the authoritative content or absence, with the edit state cleared.
- [ ] A held move response overlapped by a newer remote edit, move or soft-delete of the same card ends in the authoritative quadrant, with _moving cleared and no card left in the optimistic quadrant.
- [ ] The soft-delete path and every Realtime fold clear their optimistic entry and rerender the card's current quadrant plus every quadrant the optimistic entry showed it in.
- [ ] Existing integration tests for insert, edit, delete, relocate, pending move, rollback and propagation still pass, and cross-client propagation stays under 2000ms without polling.
